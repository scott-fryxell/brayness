## Vault layout

## Tracker

`tracker.md` is a single table, most recent activity first:

| Company | Role | Stage | Next action | Date |
| ------- | ---- | ----- | ----------- | ---- |

Update it whenever a company's stage changes. This is the answer to "where do things stand" -- don't make the user open every company note to get status.

## Hiring process stages

Typical order, though companies skip/reorder steps:

1. Application / referral
2. Recruiter screen
3. Hiring manager screen
4. Technical round(s) (coding, system design, or both)
5. Onsite / final loop
6. Reference checks
7. Offer
8. Negotiation
9. Decision

When the user names a target company, ask (or research) what their actual loop looks like rather than assuming all 9 steps apply.

## Follow-up etiquette

- Thank-you note within 24 hours of each round, sent to the specific interviewer if contact info exists, referencing something specific from the conversation (not generic).
- If no word by the timeline the recruiter gave, one polite check-in is normal; more than that reads as pressure.
- Log every outreach in the company note's `## Follow-up log` table so nothing gets sent twice.

## Negotiation basics

- Research comp for the role/level/location before any number is discussed (levels.fyi-style data, network).
- Don't accept or reject on the spot -- ask for time, even if short.
- If there are competing offers, it's fair to say so and ask for time to let them land together.
- Negotiate the whole package (base, equity, sign-on, start date, level), not just base salary.
- Know a walk-away number before the call, not during it.

## Rejection/ghosting

- A rejection is data for the next company's prep (what stage, any feedback given) -- log it in the company note rather than just closing it out.
- Past the recruiter's stated timeline with no response, treat it as a soft no and refocus energy elsewhere rather than chasing.
